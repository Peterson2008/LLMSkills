# Project Progress

把项目进度文档写成简洁、可持续维护的工作记录，而不是原始草稿或完整变更日志。

## 默认结构

1. 当前状态
2. 当前结果或指标
3. 已完成里程碑
4. 下一步

如果项目已有稳定格式，沿用现有格式，除非用户明确要求重写。

## 工作流程

1. 阅读现有进度文档，以及划定内容边界的相邻资料，尤其是决策文档和数据说明。
2. 遵守仓库级说明，例如 `AGENTS.md`、`CLAUDE.md`，并沿用项目现有的文档语言和标题风格。
3. 区分三类内容：当前状态、带日期的里程碑、尚未完成的工作。
4. 删除重复条目、低层实验轨迹，以及实际已经完成的过期待办。
5. 只保留结果层面的事实：已经交付什么、发生了什么实质变化、当前基线或结果是什么。
6. 将设计理由和指标定义留在决策或参考文档中，不要在进度文档中重复。
7. 以简短、按优先级排列的下一步结束。
8. 优先修改已有进度文档；除非用户要求，不要平行创建另一份。

## 写作规则

- 使用简短条目。
- 使用里程碑语言，不写逐步实现过程。
- 明确写出日期。
- 指标尽量带单位、基线和变化方向。
- 删除 `jd`、`wl`、`todo??`、`maybe` 等内部草稿标记。
- 不要把进度文档写成完整 changelog。
- 只写能够从现有材料或用户输入确认的事实；不能确认的内容明确标注，不得编造。

## 完成前检查

- 当前状态与最新里程碑一致。
- 已完成事项没有继续出现在待办中。
- 关键指标只出现一次，没有跨章节重复。
- 未跟进日常讨论的读者也能从上到下读懂。

需要紧凑的改写骨架时，读取 `references/template.md`。
