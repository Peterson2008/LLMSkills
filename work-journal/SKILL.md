# Work Journal

把用户当天做的工作整理成简洁条目，更新 Joplin 中固定的 `工作日志` 笔记。

## 日志规则

- 最新日期放在笔记顶部，历史内容不重排。
- 同一天的新条目追加在当天已有条目之后，编号继续递增。
- 一个项目或主题对应一个条目，不要把多个项目混成一段。
- 条目标题以动作开头，例如：完成、改进、优化、修复、调研、迁移、梳理、设计、上线、对齐。
- 标题下使用简短 bullet，说明实际完成的工作和结果。
- 只依据用户输入或真实材料整理；不添加用户没有表达的成果、原因或结论。
- 保留必要的项目名、版本号、指标、路径和技术术语，不要为了口语化而丢失关键信息。

## 输入格式

传给脚本的每个条目使用无编号的三级标题：

```markdown
### 改进 algorithm-report skill
- 收敛标题和数据缺失规则
- 补充界面元数据并完成校验

### 迁移 work-journal skill
- 合并平台无关的写作规则
- 将 Joplin 更新脚本放入 skill
```

不要自行添加条目编号；脚本根据当天已有内容统一编号。

## 工作流程

1. 从当前对话、用户指定的材料和已完成工作中提取事实。
2. 按项目或主题拆分条目，改写为动作开头的标题和简短 bullet。
3. 如果关键信息不清楚或写入意图不明确，先展示草稿并询问；不要猜测。
4. 如果用户明确要求更新工作日志，可以直接写入。希望在写入前核对时，先执行 `--dry-run`。
5. 使用 `joplin-notes` 的通用 Joplin API 能力；本 skill 只保留工作日志格式和日期编号逻辑。
6. 从 stdin 将 Markdown 传给 `scripts/prepend_worklog.py`，避免把长文本放进 shell 参数：

   ```bash
   printf '%s\n' \
     '### 改进 algorithm-report skill' \
     '- 收敛标题和数据缺失规则' \
     | python3 scripts/prepend_worklog.py update
   ```

7. 完成后报告日期、条目数和脚本返回的 Joplin 内部链接。

运行命令时，以本 `SKILL.md` 所在目录为基准解析脚本路径，不要依赖 `~/.claude` 或其他平台专用目录。

## 安全与失败处理

- 不把 Joplin token 写入 Markdown、日志、命令示例或 skill 文件。
- token 按顺序从 `--token`、`JOPLIN_TOKEN`、Joplin 桌面设置文件读取。
- 写入前由脚本读取笔记最新正文并生成完整新正文，避免用陈旧备份覆盖线上笔记。
- 连接失败时，保留整理好的 Markdown，提醒用户打开 Joplin 并启用 Web Clipper。
- 标题匹配不到或出现多条同名笔记时，不猜测目标；使用 `--note-id` 明确指定。
- 不直接修改 Joplin SQLite 数据库。

通用 Joplin 启用方式、环境变量和故障排查见 `../joplin-notes/references/joplin-setup.md`。
